## 🔧 修复

- **命中路径不再做任何缓存写回**：v0.8.1 的后台裁剪要「读-改-写」同一条 KV，而这个存储没有比较-交换——与并发生成或热重载的另一代实例交叠时，旧快照仍可能盖掉新主题，任务本身也会把缓存锁占住。现在命中只读不写；超限的旧分桶在下一次真正写入（问了新主题）时收口到 20 条。缓存仍是尽力而为：热重载前后两代实例并发写同一用户时，极端时序下可能有一个主题没写进去，下次会重新生成——这一层的 KV 没有比较-交换，无法原子合并。

**English**

## 🔧 Fixes

- **Cache hits no longer write anything back**: the v0.8.1 background trim had to read-modify-write the same KV entry, and the store offers no compare-and-swap — overlapping with a concurrent generation or the other instance during a hot reload, it could still overwrite a newer topic, and the task could pin the cache lock. Hits are now read-only; an oversized legacy bucket bag is trimmed to 20 on the next real write (a new topic). The cache stays best-effort: if the old and new instances during a hot reload write the same user's entry at the same moment, an extreme interleaving can drop one topic and it will be regenerated next time — this KV layer offers no compare-and-swap, so the merge cannot be atomic.
