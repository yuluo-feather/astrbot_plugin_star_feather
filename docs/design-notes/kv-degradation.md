# KV 降级契约

## 接口

`adapters/kv_utils.py` 是插件里唯一的 KV 访问层，只保证两件事：**读不抛、写不炸**。

- `kv_get(kv, key, default, what) -> (value, ok)`
  - `ok=True`：正常读到。**没有记录时也返回 `(default, True)`**——「没有记录」是正常语义。
  - `ok=False`：存储故障（或对象压根没有 `get_kv_data`），`value` 为 `default`。
- `kv_put(...) -> bool`：写成功与否，异常一律吞掉。
- `kv_delete(...) -> bool`：接口缺失返回 False，不算故障。

`what` 是日志上下文，排查时能看出是哪一处降级。

## 为什么必须区分「故障」与「无记录」

两者都表现为「读不到值」，但调用点的正确行为相反：

| 调用点 | 存储故障 | 无记录 |
|---|---|---|
| 限流闸门 `LimitGate.check` | 放行，且**不计数** | 正常放行并计数 |
| 每日牌运缓存 | 按确定性函数出牌，**不写回** | 正常生成并写回 |

如果接口把两者折叠成同一个 `default`，调用点就无法做出正确判断：限流会在存储故障时
把用户计成 1 次，缓存会拿空壳覆盖真实记录。

历史注记：这个模块曾因「全仓零调用」被静态检查判定为孤儿、差点按删除处置。真正的原因
是旧接口把「存储故障」与「无记录」折叠在一起，gating 无法按契约降级；修接口再接线，
比删掉模块正确。

## 使用约定

- 新的 KV 消费者一律走这里，不要自己写 `try/except`。
- 读失败后的策略由调用点决定，本层不替它做业务判断。
- 写回前如果依赖旧记录（读-合并-写），读失败时不要写回。
