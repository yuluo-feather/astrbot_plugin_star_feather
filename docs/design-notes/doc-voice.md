# 文档口吻与精简规则

README、本目录和模块头的写法约定：事实要准，句子要短，牌灵的声音只占一小块。

## 三条硬规则

1. **一段一句口吻**。每个小节最多一句带牌灵口吻的话，放段首或段尾；其余句子只陈述事实。
2. **口吻句不装新事实**。数字、路径、行为、边界写在中性句里；口吻句只做判断或收尾。
3. **口吻靠选词，不靠语气词**。「本羽说了算」「别指望它自己长出来」可以；「哼」「嘛」「啦」「哦」堆在一起不行。

## 破折号

中文破折号 `——` 一段最多一个。能用句号就换句号；连续两句都用，至少删一个。

可以：

> 牌面图排在 AI 之后才渲染；渲染失败就退回纯文本。本羽不让你空手。

不行：

> 牌面图排在 AI 之后才渲染——渲染失败就退回纯文本——本羽不让你空手。

## 少用 AI 味句式

| 少用 | 换成 |
|---|---|
| 不是 A，而是 B | 直接写 B；需要对比时写「A 不行，B 行」 |
| 首先 / 其次 / 最后 | 按实际顺序写，或直接用段落 |
| 此外 / 值得一提的是 / 综上所述 | 删掉，或写「还有一点」 |
| 在……的背景下 / 随着……的发展 | 直接写事实 |
| 全面 / 深度 / 极致 / 赋能 / 无缝 | 写具体做了什么 |
| 至关重要 / 不可或缺 | 写「不做会怎样」 |
| 总而言之 / 一句话总结 | 删掉，最后一段自然收尾 |
| 三个抽象名词并列 | 只留真正相关的那一个 |

## 段落形状

- 先给结论，再给理由，最后给边界。
- 一段只讲一件事。超过五行就拆。
- 列表用于并列事实，不用于包装段落。
- 加粗只标关键词，一行最多两处。

## 口吻配额

| 文档 | 配额 |
|---|---|
| README 开头 / 功能一句话 / 设计取舍 | 每个区块一句 |
| 本目录的注记 | 开头或结尾一句「说人话」 |
| 模块 docstring | 模块头一句；函数 docstring 保持中性 |
| changelog | 不加口吻 |

## 写完自检

1. 删掉口吻句，这一段的事实还完整吗？不完整，说明口吻句装了新事实，挪回中性句。
2. 一段里有几个破折号？超过一个就换句号。
3. 有没有「不是…而是…」「首先…其次…」？有就改写。
4. 把形容词删掉，句子还成立吗？成立就删。
