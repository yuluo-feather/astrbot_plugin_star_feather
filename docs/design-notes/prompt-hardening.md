# 提示词防护

送进模型之前的问题会经过三步，**顺序固定**：
归一化（`normalize_injection_input`）→ 截断（`clip_question`）→ 句式剥除
（`strip_injection_fragments`）。顺序颠倒会让全角/零宽写法绕过后面的正则。

## 归一化

先把绕过手段抹平，再让正则只需写标准形：

- 剥离零宽与 bidi 控制符（含 BOM、定向嵌入/隔离）；
- 全角字母数字转半角；
- 空白折叠（全角空格统一、连续空白压成一个，不动换行）。

两条红线：

1. **不转全角标点**——中文问题里的「，。？！」是正常标点，转了反而污染原文；只转
   全角字母/数字，英文注入才吃这套。
2. **保留 ZWJ / ZWNJ**（U+200C / U+200D）——它们是 emoji 序列的粘合剂，剥离会把
   正常 emoji 拆碎。

## 截断

- 默认上限来自 `settings.DEFAULT_QUESTION_MAX_LEN`（200）；
- 头尾保号：头 70% 保留主体、尾部保留关键意图（「要不要复合？」常挂在末尾），中间
  省略号；
- 头部尽量在断句处收尾，断句点太靠前则直接硬切；
- 极小上限（<10）走硬截：没有保号意义，正常配置不会走到。

## 句式剥除

原则：**只剥完整的越狱句式，不碰单字**。正常问题里撞到「忽略」「忘记」这类弱特征词
不误伤；命中即剥、剥空才回退，不把「夹带特征词但内容正常」的请求整体拒绝。

规则表里的两个技术点：

- 跨行匹配用 `[\s\S]` 而不是 `.`：`.` 不匹配换行，跨行拼接的越狱句式会漏网（实测踩过）；
- 英文指令覆盖的单词间隔放宽到 `[\s*_.-]`：星号/下划线/点做间隔的变体注入（2026-09-06
  渗透实测）。

## 输出侧

结构校验与解读解析在 `ai/parse.py`，不在本模块。松/严两档口径见
`settings.ai.structure_check` 与 README 的配置表。
