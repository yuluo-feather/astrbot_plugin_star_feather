# 每日牌运缓存

## 结构

一个用户一条记录，键是 `sf_daily_<uid>`，内容是 `DailyRecord`（schema 2）：

- 牌字段：`date` / `card_id` / `upright` / `sign`
- 解读上下文：`prompt_v` / `persona` / `interps`（主题指纹 → 解读结构）
- 牌灵字段：`spirit_line` / `spirit_sign` / `spirit_persona`

旧版本把牌灵单独放在 `sf_spirit_<uid>`，合并成单键后，牌、解读、牌灵共用同一个
日期边界；旧键在首次访问时尝试删除（删不掉下次再试），不再读取。

牌字段只能由 `put_pick` 写（`services/daily_store.py` 的 P0 结构保证）；`put_interp`
与 `put_spirit` 只改各自的上下文，不碰牌字段。

## 三条写回保护

### 1. 旧日期快照不回写（`pick_cached`）

请求在 23:59:59 取得日期快照，可能排队到另一个请求已经写入新一天的记录之后才拿到锁。
此时按自己的日期出牌，但**不写回**——否则会用旧日期覆盖掉新一天的牌面、解读与牌灵。

### 2. 生成跨过午夜不回写（`interp_cached` / `spirit_cached`）

AI 生成要几秒。写回前重新读一次：如果 KV 里的记录日期已经晚于本次快照，就直接返回
结果，不写回。这一步与第 1 条配合，堵住跨午夜的整类问题。

### 3. 读故障不写回

- `interp_cached` / `spirit_cached` 的二次读取失败时，拿不到旧记录，写回会把它覆盖成
  空壳，所以只把本次结果交给调用方。
- `pick_cached` 首次读失败时，按确定性函数出牌，但不写回。

## 失效条件（`same_context`）

命中要求四项全等：日期、牌组指纹、提示词指纹、人设。

上下文失配时的处理分三档：

| 情况 | 处理 |
|---|---|
| 同一天、同一牌组，只是人设变了 | 只清 `interps`，保留牌字段与牌灵缓存 |
| 同一天、同一牌组，提示词指纹变了 | 除清分桶外，牌灵字段一并作废（旧提示词生成的句子不能被新指纹认证） |
| 日期或牌组变了 | 整条重建 |

这一档是 v0.9.0 回归修复的产物：重构时曾用 `DailyRecord()` 从零重建，把牌字段与
牌灵缓存一起抹掉；v0.8.3 的写法是先 `dict(fresh)` 保留全部字段再改。

两条写回路径都按这一档处理：牌灵写回若发现记录的 `prompt_v` 与当前指纹不同，
同样先清空 `interps` 再写——否则它会把版本号刷新成新的，让旧提示词生成的解读
顶着新版本号被命中（普通占卜先于今日牌运时必现）。

## AI 开关

缓存里存的是 AI 产物。`ai.enable_ai=false` 时两条缓存都不读取：解读按未命中返回
（由发送层回退本地牌义），牌灵直接取池内签文；历史记录原样保留，重新开启后照旧可用。
缓存命中不是绕过配置开关的后门。

## 结构校验

缓存命中在 strict 档下复检结构：loose 时期写入的不合格解读视为未命中并重新生成；
切换档位不需要清空整条用户记录。loose 档不复检——当次生成本来就经过 loose 校验，
升级前的纯文本记录也在这条兼容路径上。

## 牌面固定不依赖缓存

`_daily_pick` 是 `md5(日期:用户)` 播种的确定性纯函数。缓存坏掉、读失败、记录被清空，
都只影响「有没有缓存」，不影响「今天这张牌是哪张」。这是缓存降级能这么激进的前提。
